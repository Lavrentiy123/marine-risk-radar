# Итоговая связка программы и n8n

Импортируйте AI_Marine_Risk_Radar_FULL.json. Это один workflow с 29 узлами. Файл v3.json заменён полным вариантом, используйте FULL.

## Настройка после импорта

1. Откройте новый пустой workflow → … → Import from File → AI_Marine_Risk_Radar_FULL.json.
2. В «ИИ-Аналитик: Синтез риска (OpenAI)» выберите свою рабочую учётную запись OpenAI.
3. В «Офицер: защищённая форма решения» оставьте Authentication = Basic Auth. Создайте credential HTTP Basic Auth с отдельными логином и сильным паролем офицера. Пароль не вставляется в программу или JSON.
4. Снимите публикацию предыдущего workflow: он использует тот же адрес API. Опубликуйте FULL.
5. Откройте index.html из этой папки заново, Ctrl+F5. app.py использует тот же файл. Адрес программы уже связан с lavrik.app.n8n.cloud.

Журнал marine_risk_events_v4 создаётся узлами Data Table автоматически при первом запросе. Если установленная версия узла не предлагает Create / Reuse Existing Tables, нужен совместимый Data Table node: не заменяйте запись временными данными. Проверка этой операции в вашем Cloud остаётся частью приёмки после импорта.

## Что теперь связано

Три входа оценки: встроенная форма, внешнее API и демо. Далее: проверка IMO/цены/маршрута → погодный API → детерминированные правила → контроль полноты → вспомогательный текст LLM → сохранение оценки в Data Table → возврат сохранённого результата программе. При ошибке записи успешного подтверждения нет.

Три дополнительные ветки: защищённая форма офицера, запись его резолюции и API статуса для программы. Согласование асинхронное: API сразу возвращает AWAITING_OFFICER, а решение появляется только после действия человека. Долгого открытого запроса на время работы офицера нет.

В программе на вкладке «Решение риск-офицера» нажмите «Открыть защищённую форму офицера». ID оценки подставляется автоматически. После ввода логина/пароля укажите имя, решение и обоснование. Затем вернитесь в программу и нажмите «Обновить решение из n8n».

Варианты: REQUEST_DATA → MORE_DATA_REQUIRED; BLOCK → OFFICER_BLOCKED; APPROVE → OFFICER_APPROVED. Для APPROVE обязательны подтверждение ручной проверки, ссылки/номера документов минимум 10 символов и обоснование минимум 30 символов. Без этих сведений сервер отклоняет согласование. Сам AI не одобряет рейс.

Имя офицера является заявленным именем после входа по отдельной Basic Auth учётной записи. Это защита общей формы, не персональная корпоративная RBAC/SSO. В журнале сохраняются все события, но таблица не является WORM: администратор n8n может менять данные. Повторные решения сохраняются новыми событиями; API показывает последнее по серверному номеру строки.

## Первый полный тест

В программе: IMO 9187655; TEST PACIFIC; Китай; Козьмино → Жичжао; цена 57,555; зона Восточно-Китайское море; цепочка пусто; порог пусто.

Ожидаем цену 57.56, карту в Азии, ID MRR-..., ожидание офицера и запись ASSESSMENT в Data Tables. Риск может быть высоким из-за реальной погоды — это не ошибка теста.

Откройте защищённую форму, выберите REQUEST_DATA и напишите «Запрошены актуальные данные AIS и документы на судно». Нажмите сохранение, затем в программе обновите решение. Ожидаем MORE_DATA_REQUIRED и отдельную строку DECISION в Data Tables. Проверьте также неверный пароль и APPPROVE без документов: решение не должно сохраниться.

Повторите исходный рейс через встроенную форму. Его результат и ID доступны в Executions / последнем узле и Data Tables. Кнопка формы сама по себе не означает разрешение рейса. Для демо используйте Execute workflow и ручной триггер; пример PACIFIC / RED_SEA / CAPE меняется в узле «Выбор демо-сценария».

## Реальные данные и ограничения

Open-Meteo Marine запрашивается из n8n и возвращает прогноз в контрольной точке с временем и единицами. Нет подстановки «спокойной» погоды при отказе. Полный прогноз вдоль маршрута с ETA пока не рассчитывается. Известные маршруты строятся по ограниченному каталогу и не являются навигационной прокладкой.

AIS, санкционные реестры, котировки и страховые тарифы пока не подключены. Для реального AIS нужны доступ к поставщику и MMSI/IMO, поэтому баллы AIS не выдумываются. Сценарный порог цены не является правовым лимитом. Итоговый балл — максимум известных индикаторов, а не вероятность происшествия.

26 локальных проверок общего движка и дополнительные проверки FULL находятся в test-results-v3.json и test-results-full.json. Это проверки кода, не доказательство успешной публикации в вашем аккаунте. После импорта необходим первый полный тест, описанный выше.
