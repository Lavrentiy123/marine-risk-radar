# Подключение версии 3

## Что изменено

index.html открывается как прежде. Общие поля и правила находятся в risk-engine.js и автоматически включаются в HTML и новый JSON workflow. app.py использует тот же HTML. Все рейсы получают AWAITING_OFFICER. Никто автоматически не записывает одобрение от имени специалиста.

Программа показывает только ответ n8n версии 3.0.0 и проверяет ID запроса, IMO, параметры и числовые правила. Старый ответ или отказ связи не заменяется локальным результатом. При изменении полей предыдущая карточка скрывается.

## Импорт в n8n

1. Скачайте резервную копию текущего workflow через меню … → Download.
2. Создайте новый workflow и выберите … → Import from File → AI_Marine_Risk_Radar_Workflow_v3.json из этой папки. Импортируйте в новый пустой workflow, не вставляйте поверх старых узлов.
3. Откройте узел ИИ-Аналитик и выберите свою рабочую учётную запись OpenAI. Модель готовит вспомогательный список проверки. Она не назначает баллы и не одобряет рейс. Её ошибка не должна подменять данные расчёта.
4. Снимите публикацию старого workflow: один адрес marine-risk-voyage-check не должен обслуживаться двумя процессами.
5. Опубликуйте новый. У Webhook уже заданы POST, marine-risk-voyage-check, When Last Node Finishes, First Entry JSON, CORS *. Отдельный Respond to Webhook не нужен.
6. Откройте index.html заново и обновите страницу Ctrl+F5. Адрес API уже установлен: https://lavrik.app.n8n.cloud/webhook/marine-risk-voyage-check.
7. У встроенной формы откройте НОВЫЙ Production URL. Старая ссылка относится к старому workflow.

## Поля в форме и программе

IMO, название судна, страна/покупатель (свободный текст), маршрут, цена, критическая зона, дополнительные зоны и необязательный порог цены. Сервер принимает те же 8 полей. Выпадающие подсказки в терминале не ограничивают серверный ввод страны или зоны.

Цена принимает точку или запятую, до 6 знаков после разделителя. Хранение после округления до центов: 57,555 → 57.56; 59.995 → 60.00. Знаки минус, экспонента, несколько разделителей и нулевая цена отклоняются. Необязательный порог является параметром учебного сценария, не действующим правовым ограничением.

## Проверка после импорта

Используйте учебное имя судна. Правильная контрольная сумма IMO не подтверждает существование или идентичность реального судна.

| Случай | Ввод | Что проверять |
|---|---|---|
| Тихий океан | IMO 9187655, TEST PACIFIC, Китай, Козьмино → Жичжао, цена 57,555, зона Восточно-Китайское море, дополнительные зоны пусто, порог пусто | Цена 57.56, карта в Азии, моря из каталога указаны явно, AIS неизвестен, AWAITING_OFFICER |
| Другой коридор | IMO 9456783, TEST RED SEA, Индия, Новороссийск → Мундра, 59.80, Баб-эль-Мандеб, дополнительные зоны пусто | Карта Чёрное море / Суэц / Красное море, красный маршрутный индикатор 88, ожидание офицера |
| Обход | IMO 9312341, TEST CAPE, Индия, Приморск → Вадинар, 58.50, мыс Доброй Надежды | Другая схема, через Датские проливы и Африку. При высокой живой волне погодный индикатор может быть красным |
| Ошибочная зона | Тихоокеанский случай плюс дополнительный Баб-эль-Мандеб | Противоречие маршрута, в программе запрос не отправляется. В форме сервер возвращает VALIDATION_FAILED |
| Граница цены | В первом случае порог 60, цена 59.995, затем 60.01 | Сначала 60.00 и ценовой индикатор 15, затем 90. Остальные причины показываются отдельно |
| Неизвестный маршрут | IMO 9187655, Китай, Порт А → Порт Б, зона неизвестный пролив | Нет выдуманной линии на карте. Предупреждения о непроверенном маршруте и зоне |
| Ошибка IMO | Заменить номер на 1234561 | Терминал блокирует до API, серверная форма тоже отклоняет |
| Отказ связи | Отключить интернет в терминале и отправить валидный случай | Нет карточки нового расчёта и локального подставного решения, видно сообщение ошибки |

Каждый успешный запрос из программы должен появиться в Executions как Webhook. Сравните поля и оценки JSON последнего узла с паспортом, скачанным из программы. Прогоните первый случай через встроенную форму: параметры и баллы должны совпасть при одинаковом погодном ответе. При разном времени запроса сравните источник, время и волну. Демо запускается Execute workflow с выбором ручного триггера; кнопка Execute step выполняет только выбранный узел, а не гарантирует полный сценарий. Сценарий меняется в узле «Выбор демо-сценария»: PACIFIC / RED_SEA / CAPE.

Зелёный Execution означает, что процесс исполнился. Он не подтверждает полноту данных или разрешение выхода судна.

## Источники и ограничения

Погода: реальный запрос Open-Meteo Marine из n8n, ближайший час UTC в пределах 3 часов, нулевые значения допустимы. Берётся одна контрольная точка, а не прогноз вдоль всего рейса по ETA. При ошибке или null погода неизвестна. Течение отображается в единицах, которые вернул сервис. Это модельный морской прогноз, не измерение с борта.

Каталог поддерживает Козьмино–Жичжао, Новороссийск–Мундра/Вадинар и Приморск/Усть-Луга–Мундра/Вадинар через явно выбранный Суэц или мыс. Схемы приблизительные. Неизвестные маршруты требуют специалиста, а не автоматически достроенного произвольного пути. Доступного глобального морского маршрутизатора в проекте нет.

Реальный AIS, санкционные реестры, страховка, состояние судна, новости UKMTO и текущие котировки пока НЕ подключены. Отсутствие данных не означает низкий риск. Общий балл — максимум известных сценарных индикаторов: зелёный <40, жёлтый 40–64, красный ≥65. Это не откалиброванная вероятность происшествия и не разрешение на выход. Для неизвестных проверок показывается null.

AISStream требует серверный API-ключ, WebSocket-приёмник и MMSI. Ключ нельзя вставлять в браузер или публичный JSON. Для интеграции нужен доступ к аккаунту поставщика и проверенные реальные IMO/MMSI. Отсутствие сообщения AIS само по себе не доказывает отключение транспондера или спуфинг.

Решения офицера пока сохраняются только в браузере, без серверной авторизации и WORM. Из UI убраны заявления о неизменяемом аудите и электронной подписи. Для рабочего внедрения нужны авторизация, серверная запись резолюций и история доказательств. Автоматического выпуска рейса нет.
